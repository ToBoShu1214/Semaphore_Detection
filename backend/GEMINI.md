# 🚩 旗語辨識教學系統 (Semaphore Recognition & Teaching System) - 全維度技術開發白皮書

本文件為本專案的的核心技術知識庫，詳盡紀錄了系統架構、通訊協議、核心演算法邏輯、軟體產品化技術以及自 2025 年 9 月啟動至今的完整開發里程碑。

---

## 一、 專案核心設計與教育願景
本專案的核心競爭力在於 **「可解釋的量化教學 (Explainable Quantitative Teaching)」**。
- **技術轉型**：捨棄傳統「影像分類 (Image Classification)」黑箱模型，改採「姿態估計 (Pose Estimation)」獲取人體骨架座標。
- **設計哲學**：將複雜的骨架座標轉換為具備幾何意義的「純向量夾角」，使系統能像人類教練一樣理解動作的結構。
- **核心價值**：透過角度偏差運算，生成具備物理空間感的校正指令（如：抬、降、跨越中線），實現真正的教學輔助而非單純的對錯判定。

## 二、 系統架構與通訊資料流 (Architecture & Data Flow)

### 1. 通訊架構 (FastAPI + React)
系統採用前後端分離架構，透過全雙工 WebSocket 連線實現低延遲同步：
- **後端 (Backend)**: Python FastAPI 負責處理影像流、YOLO 推論、FSM 狀態機轉換與校正建議計算。
- **前端 (Frontend)**: React (TypeScript) 負責 Canvas 高頻渲染、音效系統觸發與交互邏輯。

### 2. WebSocket 資料結構 (Payload Specifications)
後端傳送給前端的每一幀 JSON 數據包含以下關鍵欄位：
- `image`: Base64 編碼的 JPEG 影像。
- `state`: 目前狀態機位置（如 IDLE, READY, COOLDOWN）。
- `prompt_code`: 前端提示代碼，用於顯示「請雙手放下」等文字。
- `left_angle` / `right_angle`: 經過平滑化處理後的實時手臂角度。
- `correction_data`: 
    - `target_signal`: 目前目標字元的下一個信號。
    - `l_advice` / `r_advice`: 具體的抬降建議（如「抬 15°」、「往對面擺」）。
    - `is_correct`: 判定目前姿勢是否完全達標。
- `challenge_info`: 
    - `target_string`: 練習的總字串。
    - `current_word_index`: 目前挑戰到第幾個字。
    - `current_char_next_digit_index`: 目前字元挑戰到第幾個信號位（1-4）。

### 3. 雙模型協同處理邏輯
- **姿態模型 (`yolo11s-pose.pt`)**：
    - 追蹤 17 個關鍵點座標。核心運算基準為肩膀 (5, 6)、手肘 (7, 8) 與手腕 (9, 10)。
- **旗幟模型 (`flag.pt`)**：
    - 用於目標鎖定（Target Acquisition）。
    - **智慧鎖定演算法**：計算手腕點與旗幟邊界框四個角落的歐幾里得距離。若距離 < 150px 則判定該人為「旗手」並進行 ID 鎖定。
    - **效能控制**：鎖定目標後，旗幟偵測降至 5 幀一次或暫停，以極大化 GPU 推論 FPS。

## 三、 引擎核心演算法 (Engine Core Logic)

### 1. 座標歸一化與角度計算
- **歸一化處理**：以肩膀到骨盆的中心向量作為垂直基準線，排除使用者站姿歪斜導致的角度誤差。
- **360° 空間向量**：使用 `atan2(y, x)` 計算雙臂向量相對於身體中線的夾角。
- **平滑化視窗**：使用 `collections.deque` 維持最近 5 幀的移動平均，消除關鍵點偵測產生的雜訊抖動。

### 2. 教學校正導引演算法 (核心亮點)
系統採用基於 **180° 物理中線判定** 的抬降導引邏輯，解決了傳統角度相減在跨越身體中線時會產生指令反向的問題：
- **物理座標定義**：180° 為物理高度最高點（頂點），0°/360° 為物理最低點（底點）。
- **側別邏輯判定**：
    - 角度 > 180° 為「對向側（Cross-body）」，角度 <= 180° 為「同向側」。
    - 若手部側別錯誤（目標在對面但手在同側） -> 提示 **「往對面擺」**。
    - 若手部側別過頭（目標在同側但手在對面） -> 提示 **「擺回原側」**。
- **動態抬降指令**：
    - **同向側 (0°~180°)**：數值越大越高。`目前 < 目標` 則抬高，`目前 > 目標` 則放低。
    - **對向側 (180°~360°)**：數值越小越高。`目前 < 目標` 則放低，`目前 > 目標` 則抬高（數值邏輯反轉）。

### 3. 有限狀態機 (FSM) 詳細流程
- **`IDLE` (閒置)**：偵測目標身分，等待「交叉雙手」啟動。
- **`WAITING` (準備)**：要求雙手放下位移至 0°，作為校準起始。
- **`READY` (就緒)**：主動監聽動作。教學模式在此狀態即時輸出 `correction_data`。
- **`DETECTING` (穩定偵測)**：初步偵測到信號後進入 0.4s 的穩定計時。
- **`GRACE_PERIOD` (判定緩衝)**：執行「手臂伸直」判定。具備 1.5s 遲滯機制防止瞬間誤報。
- **`COOLDOWN` (冷卻恢復)**：信號採計成功後，強制使用者必須將手放下才能輸入下一個數字。

## 四、 軟體產品化技術 (Packaging & Optimization)

### 1. 原生視窗化實作
- **啟動層 (`launcher.py`)**：整合 `pywebview` 引擎，啟動 FastAPI 服務的同時，呼叫系統底層瀏覽器元件進行渲染，隱藏網址列與分頁標籤。
- **自動化延遲**：內建 6s 啟動遲滯，確保 YOLO 模型完全載入 GPU 顯存後才顯示介面。

### 2. 打包技術細節 (`app.spec`)
- **資源映射**：定義模型、CSV 對應表、前端 build 資料夾的內部封裝路徑。
- **隱藏依賴**：解決 PyInstaller 無法自動追蹤 `uvicorn` 與 `webview` 動態模組的問題。
- **專屬圖示**：使用 Python 腳本繪製紅黃旗語圖標並完成 ICO 封裝。

### 3. GPU 加速與佈署
- **硬體自適應**：啟動時自動檢測 `torch.cuda.is_available()`。
- **FP16 運算**：在 NVIDIA GPU 環境下開啟半精度運算，實現推論幀率最大化。
- **分卷發佈策略**：因體積超過 2GB，採用 1500M 分卷壓縮策略發佈至 GitHub Release。

## 六、 後續改進與研發方向 (Future Roadmap)

### 1. 深度演算法研發
- **3.5D 姿態補全系統**：針對側身動作導致的關鍵點遮擋問題，導入 Kalmann Filter 或時序預測模型進行點位補全。
- **自動動態校準**：在 IDLE 狀態自動分析使用者肢體長度比例，動態調整 `STRAIGHT_ARM_RATIO` 以適應不同體型（如兒童）。

### 2. 交互體驗擴充
- **互動式語音教練 (TTS)**：將「抬高」、「放低」等指令整合語音合成技術，實現無需盯視螢幕的「語音教學」。
- **AR 虛擬投影回饋**：在網頁 Canvas 上即時繪製 3D 虛擬旗幟疊加於使用者手部，強化視覺學習效果。

### 3. 教育數據化工程
- **練習軌跡大數據報告**：練習結束後將 `angle_diff` 誤差紀錄轉換為數據分析報表（如：平均誤差、進步曲線），並產出量化成績單。
- **多人同步競技模組**：擴展 WebSocket 進程管理，支援多個目標同時進行辨識與速度競賽。
